# BiBi MCP: портфель, котировки и взносы

Приложение 1.3.0, MCP 1.1.0. ИИ работает с сохранённым портфелем, получает котировки MOEX, сохраняет историю и моделирует повторные взносы. Сделки и поручения брокеру отсутствуют

## Запуск

Нужен Node.js 20+. Из корня проекта:

```shell
npm ci --prefix mcp --ignore-scripts
npm --prefix mcp test
npm run workspace
```

Откройте http://127.0.0.1:4188/. Эта локальная страница и MCP используют одно хранилище. Можно создать портфель в интерфейсе либо через ИИ; изменения появятся с другой стороны автоматически

Для Codex из PowerShell, если сервер bibi ещё не настроен:

```powershell
$bibiNode = (Get-Command node).Source
$bibiServer = (Resolve-Path ./mcp/server.mjs).Path
codex mcp add bibi -- $bibiNode --max-old-space-size=128 $bibiServer
codex mcp get bibi
```

Перед настройкой сохраните резервную копию ~/.codex/config.toml вне репозитория. Не перезаписывайте существующий bibi без проверки пути. После изменения инструментов переподключите MCP или перезапустите Codex. Запускайте именно node …/mcp/server.mjs, не npm start: stdout содержит только протокол

## Запрос для ИИ

> Используй BiBi MCP. Найди SBER и GAZP, получи котировки и лоты. Создай учебный портфель: 70 SBER и 30 GAZP, цель 50/50, денег 0, комиссия 0,05%, минимум 0. Получи новые цены через refresh_quotes и сохрани набор через apply_quotes. Рассчитай и сохрани взнос 20 000 ₽. Создай отдельную модель личного портфеля, рассчитай в ней первый взнос, учти его только в модели и рассчитай второй. Далее используй ID портфеля: позиции и остаток должен загружать сервис. Личные позиции не меняй, сделки не исполняй

## Инструменты

| Инструмент | Действие |
|---|---|
| bibi_search_securities / bibi_get_quote | Поиск бумаг / цена, лот, время и источник |
| bibi_list_portfolios / bibi_get_portfolio | Список / сохранённые позиции и история |
| bibi_create_portfolio | Создать и выбрать портфель |
| bibi_update_portfolio | Изменить явно заданный пользователем план |
| bibi_select_portfolio | Выбрать портфель в локальном интерфейсе |
| bibi_refresh_quotes | Получить все цены и временный refreshId; не записывает |
| bibi_apply_quotes | Сохранить набор по ID без внешних запросов |
| bibi_calculate_saved | Загрузить позиции и сохранить расчёт; покупки не записывает |
| bibi_create_simulation | Создать отдельную модель, сохранив исходный портфель |
| bibi_simulate_calculation | Однократно учесть расчёт только в модели |
| bibi_validate_plan / bibi_calculate_contribution | Прежние инструменты без сохранения |

Записывающие инструменты имеют readOnlyHint:false. Запись требует актуальной expectedRevision. При CONFLICT загрузите свежий портфель и проверьте намерение пользователя, не перезаписывайте автоматически. Браузер сохраняет несохранённые правки локально и предлагает скачать копию/загрузить свежую версию

Набор цен хранится в памяти MCP 120 секунд, максимум 8 наборов. Чужой, повторный или просроченный ID отклоняется. После переподключения MCP получите цены заново. Ошибка любой котировки не меняет портфель

## Хранение и ограничения

- ~/.bibi/workspace/portfolios.json: до 5 портфелей по 30 расчётов, максимум 5 МБ. BIBI_WORKSPACE_DIR задаётся владельцем при запуске; аргументы инструментов не принимают путей файлов. Сайт и MCP должны использовать один каталог и учётную запись ОС
- Запись защищена межпроцессным lock-файлом, ревизией, временным файлом и атомарным переключением. Предыдущая версия сохраняется в .backup. Повреждённое хранилище не заменяется новым. Файлы не зашифрованы, защита зависит от прав ОС
- Оставшийся после аварийного завершения write.lock удаляет владелец только после проверки, что записывающие процессы остановлены. Чужая блокировка автоматически не снимается
- HTTP слушает только 127.0.0.1, проверяет Host, Origin, HttpOnly/SameSite cookie и размеры запросов. Это доверенная локальная среда, не многопользовательская авторизация. Локальные программы с доступом к сессии считаются доверенными. Не публикуйте порт через VPS или прокси. В npm start API портфелей отключён
- Публичный kiton.pw/bibi/ и переносимый HTML сохраняют browser storage отдельно. Старые данные оттуда автоматически не читаются. Для первого переноса старой копии есть восстановление резервного файла в локальной странице. Затем переносить позиции и расчёты между ИИ и интерфейсом не нужно. На другом компьютере или у Димы хранилище отдельное
- Только MOEX ISS, рублёвые акции/фонды TQBR/TQTF. При сетевой ошибке используется фиксированный HTTPS-прокси kiton.pw/bibi/api/. Передаются только тикер/поисковая строка, не позиции, доли или суммы. Redirect запрещён, размер и время ответа ограничены, данные проверяются
- Цены могут быть задержанными или предыдущей сессии; кеш источника действует до 60 секунд. Источник, время и delayed возвращаются явно. Потоковых цен исполнения нет
- В обычном расчёте деньги …Kopecks — целые копейки; priceTicks — 0,0001 ₽. В calculation.result сохранённого расчёта contribution, purchaseTotal, fees, cash также в копейках; rows[].price — в 0,0001 ₽
- ИИ не выбирает бумаги/доли, не обещает доходность и не получает брокерские ключи. Симуляция не меняет личные позиции. Данные чата обрабатываются по правилам ИИ-клиента

Проверки: npm test; npm --prefix mcp test; node quality/browser.mjs; node quality/workspace.mjs. Детерминированные тесты используют синтетические фикстуры; реальная модель и реальный источник проверяются отдельно
