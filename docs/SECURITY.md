# Границы безопасности BiBi

## Локальный MCP 1.1 / приложение 1.3

Новая локальная версия добавляет хранение портфелей вне репозитория и публичные котировки. Историческое описание read-only MCP ниже относится к 1.2. Текущие инструменты: `mcp/README.md`

- Публичный сервер не получает API портфелей. Отдельный `workspace-server.mjs` слушает только loopback; браузер ограничен Host, Origin, HttpOnly/SameSite cookie и размером запроса. Это доверенная локальная среда, не авторизация для публичного сервера
- Только фиксированный файл, максимум 5 МБ. Пути/URL инструменты не принимают. Повреждённый файл сохраняется; временная запись, lock и ревизия защищают от частичного сохранения и потери параллельных правок. Предыдущий файл сохраняется как `.backup`; шифрования нет
- Чтение котировок отделено от записи. Предпросмотр не меняет портфель; сохранение принимает ID набора, ревизию и ID портфеля. Набор ограничен сроком и процессом. Ошибка любой бумаги не меняет данные
- Личные позиции не меняются после расчёта. Для гипотетического взноса создаётся отдельная demo-модель; повторное/устаревшее применение блокируется. Торговых инструментов и брокерских секретов нет
- Локальная страница и MCP читают одно хранилище. Поздний polling не откатывает свежую запись; конфликт не перезаписывается автоматически. Публичное browser storage отдельно и не сканируется

## Данные и доверие

Веб-портфель хранится в браузере, не содержит брокерских ключей и не передаётся серверу расчётов: формула работает локально. Поиск/котировки передают тикеры и строку запроса в фиксированный ISS endpoint. Имена и метаданные в копиях/ответах считаются недоверенными. Анонимные отзывы — только агрегаты трёх ответов, не уникальные пользователи.

Развёрнутый путь `/bibi/` имеет общий origin с kiton.pw: это не изоляция браузерного хранилища от другого кода этого домена. Подключение к банковским счетам или независимый публичный продукт потребует отдельного решения о домене, авторизации, хранении и согласии.

## Изменения этой итерации и регрессии

| ID | Приоритет | Основание в коде | Изменение и проверка |
|---|---|---|---|
| CSV-01 | Средний, зависит от табличного клиента | Экспорт проверял только первый символ строки | `src/export.mjs` нейтрализует формулы после начальных пробелов/контролов и совместимых Unicode-символов; unit + браузерный импорт/экспорт |
| HTTP-01 | Умеренный, ограничение локального HTTP | Сервер доверял произвольному Host при построении локального origin | `server.mjs` разрешает loopback и явно заданный hostname, отклоняет абсолютный proxy-target; регрессии в `tests/security.test.mjs` |
| DATA-01 | Низкий, целостность интерфейса | После await отзыва использовалась глобальная текущая запись | Ответ связан с исходной записью и состоянием; другой диалог не закрывается; регрессия в трёх браузерах |
| ENTRY-01 | Эксплуатационный | Сравнение argv с путём модуля не учитывало symlink | Сравниваются реальные пути; запуск через symlink/junction проверяется отдельным дочерним процессом |

Дополнительно: точная проверка JSON media type, запрет redirect у биржевого fetch, доступное имя диалога и ясный текст удаления данных. Изменения не означают, что на опубликованном сайте уже сменился релиз.

## Защита веб-сервера

- Только явно перечисленные публичные файлы; служебные файлы, MCP-код, зависимости и документация не раздаются.
- Origin проверяется для браузерных отзывов; запрос ограничен 2 КиБ, присутствуют rate limit и таймауты.
- CSP ограничивает скрипты текущим origin, запрещены frame ancestors и произвольная base URL. Стили содержат существующий `unsafe-inline` из-за шаблонов; скриптам он не разрешён.
- Внешние запросы используют фиксированный HTTPS-хост, строгий тикер, лимит размера ответа, таймаут и ограниченную конкуренцию.
- HTTP-код не является авторизацией. Анонимный клиент всё ещё может отправлять повторные отзывы в пределах лимитов; эти агрегаты нельзя выдавать за независимых людей.

## MCP

Локальный stdio-сервер принимает только явные аргументы двух расчётных инструментов и два статических URI. Строгие схемы, лимит 12 активов и 64 КиБ на сообщение, единицы в ответе. Торговля, HTTP-вызовы, чтение произвольных файлов, browser storage, токены и запись состояния не поддерживаются. Аннотация read-only подтверждается кодом и тестами, сама по себе она не обеспечивает безопасность.

Зависимости MCP отделены от веб-приложения, закреплены lock-файлом. Для HTTP MCP нужен отдельный проект авторизации и разграничения данных. Не переносить брокерские токены через инструмент «для удобства». Передача портфеля выбранному ИИ-клиенту подчиняется правилам обработки данных этого клиента.

## Проверки и ограничения

`npm test`, `npm --prefix mcp test`, `npm --prefix quality test`. Конкретные результаты последнего запуска доступны в локальных артефактах `qa/agent-ready`; до заявления об актуальном состоянии повторить команды.

Это инженерная проверка указанного объёма, не независимый penetration test, не подтверждение всех банковских требований и не гарантия отсутствия уязвимостей. Не проверяются чужие сайты/аккаунты, реальные портфели и торговые операции.
